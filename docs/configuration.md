# Configuration reference

Getter stores one configuration and identity per `--home`. The file is
`<home>/config.toml`, mode `0600` on Unix, parsed with `deny_unknown_fields`.
Changing values requires restarting the affected service; there is no hot
reload.

Location resolution:

1. explicit `--home <DIR>`;
2. `$GETTER_HOME`;
3. `$HOME/.getter` (or `%USERPROFILE%\.getter`).

`--home` and `--json` are global CLI options and can appear before or after the
subcommand. `getter config path` prints the active path without loading secrets;
`getter config show` prints the parsed TOML with paths (never token/key
contents).

## Coordinator example

Generated by a default `getter init --role coordinator --name home-coordinator`:

```toml
version = 1
role = "coordinator"
name = "home-coordinator"

[coordinator]
bind = "127.0.0.1:47810"
public_url = "https://127.0.0.1:47810"
database_path = "/home/you/.getter/data/getter.db"
allow_insecure_remote = false

[coordinator.tls]
ca_cert = "/home/you/.getter/tls/ca.pem"
cert_chain = "/home/you/.getter/tls/server.pem"
private_key = "/home/you/.getter/tls/server-key.pem"

[coordinator.discovery]
enabled = false
port = 47812
interval_secs = 5

[coordinator.limits]
max_tasks_per_job = 1000
max_artifact_bytes = 16777216
max_total_input_bytes = 16777216
max_total_output_bytes = 67108864
max_http_body_bytes = 50331648
max_result_bytes = 1048576
allow_trusted_verification = false
heartbeat_timeout_secs = 20
```

`discovery.target` is optional and omitted when unset. The TLS table is omitted
when `--no-tls` is used (loopback development only).

## Worker example

Generated by a default `getter init --role worker --name home-worker`:

```toml
version = 1
role = "worker"
name = "home-worker"

[worker]
coordinator_url = "http://127.0.0.1:47810"
concurrency = 3
max_task_memory_bytes = 268435456
max_task_timeout_secs = 300
max_output_bytes = 1048576
max_fuel = 5000000000
max_download_bytes = 16777216
poll_interval_ms = 750
heartbeat_interval_secs = 5
request_timeout_secs = 30
control_bind = "127.0.0.1:47811"
pause_on_battery = true
niceness = 10
lease_safety_secs = 3
allow_insecure_remote = false
```

`coordinator_ca` is added (with an absolute path) when TLS is configured or the
worker is initialized/joined with `--ca-cert` / `--ca-fingerprint`. `niceness`
is omitted if set to `none`; on non-Unix platforms it has no effect.

## Coordinator fields

### Top level

| Field | Default | Meaning / constraints |
| --- | --- | --- |
| `version` | `1` | Config schema version; unknown versions are rejected |
| `role` | `"coordinator"` | Must be `coordinator`; a coordinator file must not contain `[worker]` |
| `name` | `getter-coordinator` on `init` | Non-empty, ≤128 bytes, no control characters; display name |
| `[coordinator]` | required | Coordinator-only table |

### `[coordinator]`

| Field | Default | Meaning / constraints |
| --- | --- | --- |
| `bind` | `127.0.0.1:47810` | Listen address. `--lan` uses `0.0.0.0:47810` |
| `public_url` | derived | URL used in pairing output and by CLI clients. Must be `http` when TLS is off and `https` when TLS is on; ≤512 bytes. For an unspecified bind, must not contain `0.0.0.0` |
| `database_path` | `<home>/data/getter.db` | SQLite path; parent created by the store. Mode `0600` on Unix |
| `tls` | generated by default | Optional table. Omit only for loopback development; see below |
| `discovery` | disabled | Optional discovery table |
| `limits` | defaults below | Admission/HTTP/result capacity limits |
| `allow_insecure_remote` | `false` | **Dangerous.** Permits a non-loopback bind without TLS. Never enable outside an isolated lab |

`public_url` must be reachable by workers and admins. It is not automatically
rewritten when `bind` changes. Changing one usually requires changing the other
and restarting; workers may need a new `coordinator_url`.

### `[coordinator.tls]`

| Field | Meaning |
| --- | --- |
| `ca_cert` | CA certificate PEM; public, copied to workers. Must contain **exactly one** certificate; multi-certificate bundles are rejected |
| `cert_chain` | Server certificate chain PEM |
| `private_key` | Server private key PEM, `0600`; must differ from the certificate paths |

`init` generates a local CA and a server certificate for `localhost`,
`127.0.0.1`, `::1`, the bind IP (or all local interface IPs when binding
`0.0.0.0`), and any `--hostname` values. The CA private key is discarded after
signing. There is no ACME, online rotation, or hot reload.

### `[coordinator.discovery]`

| Field | Default | Meaning / constraints |
| --- | --- | --- |
| `enabled` | `false` | Send UDP announcements; `--lan` or `--discovery` turns it on |
| `port` | `47812` | Non-zero UDP port |
| `interval_secs` | `5` | 1–300 |
| `target` | absent (broadcast) | Optional unicast `IP:port`; if set, announcements go there instead of `255.255.255.255:<port>`. Not settable via `config set` |

Discovery is unauthenticated and grants no trust. See
[Local network](local-network.md).

### `[coordinator.limits]`

| Field | Default | Meaning / constraints |
| --- | --- | --- |
| `max_tasks_per_job` | `1000` | 1–1,000 |
| `max_artifact_bytes` | `16777216` (16 MiB) | 1–16 MiB. The runtime/worker module ceiling is 16 MiB |
| `max_total_input_bytes` | `16777216` (16 MiB) | 1–16 MiB, summed over task input strings |
| `max_total_output_bytes` | `67108864` (64 MiB) | Sum of declared task `output_bytes`; must be ≥ `max_result_bytes`, ≤64 MiB |
| `max_http_body_bytes` | `50331648` (48 MiB) | Global request body cap. Must be ≥ encoded artifact + total inputs + 1 MiB and ≤64 MiB |
| `max_result_bytes` | `1048576` (1 MiB) | Coordinator result acceptance cap; 1–1 MiB. Per-task `output_bytes` is independently ≤1 MiB |
| `allow_trusted_verification` | `false` | Permit `verification.mode = "trusted"` jobs. Development only; results are unverified |
| `heartbeat_timeout_secs` | `20` | 5–600; workers older than this are offline. Also bounds scheduler liveness |

The minimum body formula in words: base64 of the maximum artifact expands by
about 4/3, plus the maximum total raw inputs, plus 1 MiB of JSON/API overhead.
Defaults satisfy it. If you raise `max_artifact_bytes` or
`max_total_input_bytes`, raise `max_http_body_bytes` accordingly or config
validation will fail.

A job's declared output-limit sum and per-task inputs are checked at admission.
Actual outputs are also bounded per task and by the body limit. The public
enrollment endpoint has its own 64 KiB JSON body cap, independent of
`max_http_body_bytes`.

## Worker fields

### Top level

| Field | Default | Meaning / constraints |
| --- | --- | --- |
| `version` | `1` | Config schema version |
| `role` | `"worker"` | Must be `worker`; a worker file must not contain `[coordinator]` |
| `name` | `getter-worker` on `init` | Non-empty, ≤128 bytes, no control characters |
| `[worker]` | required | Worker-only table |

### `[worker]`

| Field | Default | Meaning / constraints |
| --- | --- | --- |
| `coordinator_url` | `http://127.0.0.1:47810` | Must be `http` or `https`. Plaintext non-loopback requires `allow_insecure_remote = true`; HTTPS requires `coordinator_ca` |
| `coordinator_ca` | absent | Path to the pinned coordinator CA PEM, normally `<home>/trust/coordinator-ca.pem`; required for HTTPS |
| `concurrency` | CPUs−1, clamped 1–4 | Maximum CPU slots (1–128); tasks consume `cpu_slots` |
| `max_task_memory_bytes` | `268435456` (256 MiB) | Minimum 1 MiB. Wasm linear memory ceiling per task, not an OS RSS quota |
| `max_task_timeout_secs` | `300` | 1–3,600; wall-clock guest deadline (module compilation is outside it) |
| `max_output_bytes` | `1048576` (1 MiB) | 1–1 MiB per task |
| `max_fuel` | `5000000000` | 1–100,000,000,000; Wasmtime fuel ceiling per task |
| `max_download_bytes` | `16777216` (16 MiB) | Artifact download ceiling. The runtime additionally enforces the 16 MiB module ceiling |
| `poll_interval_ms` | `750` | 100–60,000; assignment polling period |
| `heartbeat_interval_secs` | `5` | 1–300; coordinator liveness period |
| `request_timeout_secs` | `30` | 1–300; coordinator HTTP request timeout |
| `control_bind` | `127.0.0.1:47811` | **Must be loopback.** Local CLI control API; never exposed to LAN. Use different ports for multiple workers on one host |
| `pause_on_battery` | `true` | On Linux, pause when a battery reports `Discharging`; no effect without readable battery entries or on non-Linux |
| `niceness` | `10` | Unix nice value at startup (−20–19) or `none`; best-effort. No effect on non-Unix |
| `lease_safety_secs` | `3` | Abort/stop before lease expiry; ≤60. No lease-extension protocol exists |
| `allow_insecure_remote` | `false` | **Dangerous.** Permits a plaintext non-loopback coordinator URL. Lab only |

Worker limits are ceilings: a task's requirements must not exceed them. The
coordinator scheduler also avoids assigning work that does not fit a worker's
advertised capabilities. Raising a worker's limit does not force the coordinator
to use it.

## Changing configuration

Supported `getter config set` keys:

**Worker**

- `worker.concurrency`
- `worker.max_task_memory_bytes`
- `worker.max_task_timeout_secs`
- `worker.max_output_bytes`
- `worker.max_fuel`
- `worker.poll_interval_ms`
- `worker.heartbeat_interval_secs`
- `worker.pause_on_battery` (`true`/`false`)
- `worker.control_bind` (`IP:PORT`)
- `worker.niceness` (integer or `none`)
- `worker.max_download_bytes`
- `worker.coordinator_url`

**Coordinator**

- `coordinator.bind`
- `coordinator.public_url`
- `coordinator.discovery.enabled`
- `coordinator.discovery.interval_secs`
- `coordinator.limits.heartbeat_timeout_secs`
- `coordinator.limits.max_tasks_per_job`
- `coordinator.limits.max_artifact_bytes`
- `coordinator.limits.max_total_output_bytes`
- `coordinator.limits.allow_trusted_verification`

`getter config set` writes the TOML and validates it; it does not restart the
service. Restart to apply. `coordinator.limits.max_total_input_bytes`,
`max_http_body_bytes`, `max_result_bytes`, `coordinator.discovery.port`/`target`,
`worker.coordinator_ca`, `worker.request_timeout_secs`, and
`worker.lease_safety_secs` are **not** in the set allow-list; edit the TOML and
restart, keeping the file `0600`.

Examples:

```sh
getter --home ~/.getter config set worker.concurrency 2
getter --home ~/.getter config set worker.max_task_memory_bytes 536870912
getter --home ~/.getter config set worker.pause_on_battery false
getter --home ~/.getter config set coordinator.limits.max_total_output_bytes 33554432
getter --home ~/.getter config path
getter --home ~/.getter config show
```

`config set` refuses unknown keys, wrong types, and values that fail validation.
A successful output says restart is required. A failed set does not write the
file (validation happens before the atomic write).

## TLS and insecure-development overrides

- **Default:** TLS on, local CA, worker CA pinning, loopback or LAN.
- **Loopback plaintext:** `getter init --no-tls --bind 127.0.0.1:47810` is
  allowed for local development. An admin token and worker signatures still
  apply, but traffic is not encrypted.
- **Remote plaintext:** requires `allow_insecure_remote = true` in the
  coordinator and/or worker TOML. This is refused by default and is only
  appropriate on an isolated test network with no untrusted hosts.
- **HTTPS worker:** `coordinator_ca` must exist and be the pinned CA. `join`
  writes it under `<home>/trust/coordinator-ca.pem` and sets the path.
- **CA changes:** reinitialize/re-enroll. There is no online rotation.

A coordinator `public_url` with `https` and no `[coordinator.tls]` is invalid;
`http` with TLS configured is also invalid. Check `getter doctor` after changes.

## Environment variables

| Variable | Effect |
| --- | --- |
| `GETTER_HOME` | Default home when `--home` is omitted |
| `RUST_LOG` | `tracing` filter for coordinator/worker/CLI logs (for example `info`, `getter_coordinator=debug`) |
| `CARGO` | Build script only: cargo binary used by `scripts/build-example.sh` |
| `GETTER_BIN` | E2E harness only: binary to reuse |

`HOME`/`USERPROFILE` determine the default home. There is no config-directory
search path or per-job environment passed to guests (the guest has no
environment at all).

## Validation summary

The config loader rejects:

- missing files, non-UTF-8 content, TOML syntax errors, and unknown fields;
- unknown `version`, wrong role/table combinations, empty/oversized names with
  control characters;
- a non-loopback plaintext coordinator bind without `allow_insecure_remote`;
- a non-loopback plaintext worker URL without `allow_insecure_remote`;
- HTTPS without `coordinator_ca`; URL scheme/database/limits inconsistencies;
- TLS private key path equal to a certificate path;
- out-of-range limits and a too-small HTTP body cap;
- non-loopback `control_bind`; a worker `lease_safety_secs > 60`; invalid
  discovery port/interval; invalid niceness on Unix.

Use `getter doctor` for a live check of parsed config, permissions, TLS,
reachability, and local control API.
